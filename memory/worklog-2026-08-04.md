2026-08-04 工作记录：**OpenCUA-7B demo 首次端到端跑通**——集群 gpu03 起 vLLM 服务，用户 Windows 笔记本经 SSH 隧道接入，模型成功输出点击动作并执行。

**环境安装收尾**（接 [[cluster-gpu-cuda-constraint]]）
- micromamba 在登录节点又被 OOM 杀：defaults 频道（pkgs/main 等）全量 repodata 是元凶 → `--override-channels -c conda-forge` 解决
- 登录节点无 GPU，解析报缺 `__cuda` 虚拟包 → `CONDA_OVERRIDE_CUDA=12.9`
- conda-forge vllm 0.19.1 带的仍是 transformers 5.14.1（没回 4.x），OpenCUAProcessor 丢 image_processor 的 5.x 坑照样存在 → 同款三行补丁打在 0.19.1 的 opencua.py，CPU 侧验证过
- conda-forge vllm 不带 CUDA 编译工具链，GPU 节点上 Triton JIT 连环报缺件：`cuda.h`（装 cuda-cudart-dev + cuda-driver-dev）→ `ptxas`（装 cuda-nvcc-tools + cuda-cuobjdump + cuda-nvdisasm）；slurm 脚本需 export PATH/TRITON_PTXAS_PATH/CUDA_HOME 指向 conda env

**服务端**
- vLLM 默认 `max_num_batched_tokens=2048` 同时是多模态 encoder 缓存上限，高分屏截图 4641 视觉 token 直接 400 报错 → slurm 启动参数加 `--max-num-batched-tokens 20480`（容得下 3 张历史截图）
- 服务就绪判据：日志出现 "Application startup complete"；curl `http://<node>:8000/v1/models` 可从登录节点直接验证

**客户端（demo_client.py，Windows 实测踩坑）**
- 鼠标动但点击不生效 → 两个修复：导入 pyautogui 前 SetProcessDpiAwareness(2)（高分屏物理/逻辑像素错位）；click 改为 move→0.1s→down→0.06s→up（瞬时 down/up 部分应用不认）
- 动作没效果时模型死循环重复同一动作 → 防重复三件套：提示里告知"屏幕没变化，换办法"+ 该步 temperature 0→0.6 + 连续 4 次熔断
- 任务完成后模型不停、跑满 15 步 → 系统提示必须显式约定 terminate(status='success')；解析器要兼容官方 `computer.*` 动作空间
- 默认改为连续执行（Ctrl+C / 鼠标甩左上角退出），`--confirm` 保留逐步模式
- 用户侧网络到 GitHub 不稳（Connection reset），备用方案：scp 从集群拷文件

**遗留**
- 模型对中文 Windows 界面定位一般，任务描述用英文、写具体（如 "click the Chrome icon in the taskbar"）效果更好
- demo 阶段结束；下一步方向待定（习惯学习管线 / AgentNet 数据流程）
