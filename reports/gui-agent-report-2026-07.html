调研报告 · 2026 年 7 月

能学习你使用习惯的 GUI Agent：现成方案选型

目标：找到操作电脑桌面应用、能长期观察你的操作习惯并自动学习、进而主动替你完成任务的现成工具与可二次开发框架。

共核实 6 个核心项目 + 若干补充选项 · 信息以 2026-07 各项目 GitHub / 官网为准

一句话结论

目前没有任何单一产品能完整做到「后台长期观察 → 学会你的习惯 → 主动替你操作」的闭环——这仍是 2026 年学术界和创业公司都在冲刺的方向。但这个闭环的三个环节各自都有成熟的现成项目，可以直接用或拼起来用：

想直接用：装 Screenpipe（24/7 本地记录你的屏幕操作，积累成可搜索的记忆库，并能据此触发自动化）+ UI-TARS Desktop（用自然语言指挥它操作你的电脑）。
想做研究/二次开发：以 Agent S3（自带经验学习机制、OSWorld 超人类水平）为执行基座，参考 ProactiveAgent（ICLR 2025，监控用户活动并主动提议）与 OpenAdapt（从演示中学习工作流）的思路，把「观察层的记忆」接到「执行层」——这正是当前的开放研究命题。

理解这个问题：三层架构

「学习我的使用习惯并帮我做事」可以拆成三层，市面上的项目基本都只占其中一到两层：

① 观察 / 记忆
在后台持续记录你在用什么 app、看了什么、做了什么操作，形成本地可查询的「数字记忆」。
代表：Screenpipe、ActivityWatch
↓ 从记录中提炼规律
② 学习 / 预测
从演示或历史行为中学出可复用的工作流，或预测「用户现在可能需要什么」并主动提议。
代表：OpenAdapt（演示学习）、ProactiveAgent（主动预测）
↓ 把意图变成动作
③ 执行
看懂屏幕，真正控制鼠标键盘去操作桌面应用，完成任务。
代表：UI-TARS Desktop、Agent S3、UFO²/UFO³

项目详情

Screenpipe

最贴合「长期观察自动学习」的一个

本地优先的 24/7 屏幕+音频记录器：事件驱动截图（切换 app、点击、输入停顿时触发），同时抓取系统无障碍树文本 + OCR，全部存进本机 SQLite——没有数据上云。之后你可以用自然语言搜索「我上周在那个网页上看到的表格」，像回放 DVR 一样浏览一整天的操作历史。

关键的是它的 Pipes 系统：用 markdown 定义的小 agent，可以查询你的屏幕记忆、按你的活动被触发、调 API 执行操作——内置了会议纪要、每日回顾、standup 汇报等。还提供 MCP server（claude mcp add screenpipe -- npx -y screenpipe-mcp@latest），可以直接把你的屏幕记忆接给 Claude。资源占用约 CPU 5–10%、每月 20GB 存储。

定位：观察记忆层的事实标准隐私：全本地，可离线

UI-TARS Desktop / Agent TARS

字节跳动 · 开源执行层里最能打的

下载即用的跨平台桌面 app：截图 → 视觉模型理解界面 → 直接控制鼠标键盘，你用自然语言描述任务即可。背后的 UI-TARS 模型在 OSWorld 等基准上超过 Claude Computer Use 与 GPT-4o，模型本身也开源（Hugging Face 可下载 UI-TARS-1.5 本地部署，也可走火山引擎/Anthropic 云 API）。生态里还有 Agent TARS CLI（npx @agent-tars/cli@latest）覆盖浏览器与终端场景，支持 MCP 扩展。

定位：即装即用的「动手」能力局限：不会自己观察学习你的习惯

Agent S3

Simular · 最适合做研究基座

2025 年 12 月发布的 S3 是第一个在 OSWorld 上超越人类水平（72.6%）的计算机使用 agent。框架自带分层规划 + episodic memory（情景记忆），会从执行经验中持续改进，并用 Behavior Best-of-N 在多条执行轨迹中选优。pip install gui-agents 即装，提供 CLI 和 Python SDK（AgentS3、OSWorldACI 类），二次开发接口清晰——如果你的研究方向是「把用户习惯记忆注入 agent」，这是最顺手的起点。需要配主模型 API（推荐 GPT-5）+ 一个 grounding 模型（推荐 UI-TARS-1.5-7B，可托管在 HF 推理端点）。

定位：执行 + 经验学习，科研首选许可：Apache 2.0

OpenAdapt

「演示一遍让它学会」路线的代表

思路与众不同：你把一个重复性任务操作一遍，它录下你的点击、键盘和屏幕证据（结构、无障碍树、视觉、OCR、空间信息），然后编译成一个确定性的本地可重放脚本——健康运行时零模型调用、零 API 费用，界面变化时才走「受控修复」流程（宁可停下也不瞎猜）。适合把你固定的高频工作流一次性固化下来。pip install openadapt[browser] 起步，另有 Windows/macOS/Linux/Citrix 扩展。

定位：演示学习 → 确定性自动化状态：Beta，1.7k★

UFO² / UFO³ Galaxy

微软 · Windows 用户的深度集成选项

UFO²（2025-04，已进入长期支持）是 Windows 专用的「桌面 AgentOS」：HostAgent 调度多个 AppAgent，混合 GUI 点击与 Windows 原生 API 调用，比纯视觉方案更稳，还能通过推测性多动作减少 51% 的模型调用。2025-11 的 UFO³ Galaxy 进一步做多设备编排（Windows/Linux/Android）。配置项较多（API key、设备池等），偏工程化。

定位：Windows 深度执行模型：GPT-4o / Azure / Qwen / Claude 均可

ProactiveAgent

清华 THUNLP · ICLR 2025 · 「主动性」研究代表作

最接近你说的「长期观察后主动帮忙」的学术实现：用 ActivityWatch（本身就是个优秀的开源行为追踪器）实时监测你在编码、写作、日常场景中的活动，agent 预测你此刻可能需要什么，通过系统托盘通知主动提议，你可以接受/拒绝/忽略——这些反馈由一个 F1=0.918 的奖励模型消化。已发布基于 LLaMA 和 Qwen 微调的专用模型。研究代码性质，工程成熟度一般，但思路和数据集对二次开发很有价值。

定位：观察 + 主动预测的研究框架依赖：ActivityWatch + LLM API

其他值得知道的

  • Browser Use — 如果任务主要在浏览器里，DOM 级操作比纯视觉方案更快更准，是网页自动化的事实标准。
  • Open Interpreter — 代码执行 + GUI 混合的万金油，适合「能用脚本就不点鼠标」的场景。
  • Claude 桌面版 / Computer Use — Anthropic 官方的计算机使用能力，商业方案里体验最完整的之一。
  • ActivityWatch — 纯观察层的轻量开源方案（只记录 app 使用时间与窗口标题，不截图），隐私顾虑最小。

两条路线的上手步骤

路线 A：即装即用（个人电脑上）

  1. 装 Screenpipe：从 screenpi.pe 下载，或源码构建（免费）。让它跑一两周，积累你的操作记忆。
  2. 装 UI-TARS Desktop：从 GitHub Releases 下载，配一个模型（最省事走云 API；有 GPU 可本地部署 UI-TARS-1.5-7B）。
  3. 连接两者：通过 Screenpipe 的 MCP server 把「你的屏幕记忆」提供给 agent，让它在执行任务时能参考你的历史习惯；再用 Pipes 把高频场景（会议纪要、日报）做成按活动自动触发的小自动化。
  4. 固定的重复性流程，用 OpenAdapt 演示一遍固化成零成本的可重放脚本。

路线 B：科研 / 二次开发

# macOS 另需: brew install tesseract
# 配置主模型 (如 GPT-5 / Claude) + grounding 模型 (UI-TARS-1.5-7B)

值得做的研究命题恰好就是现在的空白：把观察层积累的用户习惯记忆（Screenpipe/ActivityWatch 的行为流）注入执行层 agent 的规划过程。Agent S3 的 episodic memory 接口、ProactiveAgent 的需求预测数据集、OpenAdapt 的演示编译思路，都是现成的积木；相关综述可看 Large Language Model-Brained GUI Agents: A Survey。

注意事项

  • 隐私：观察类工具会记录你屏幕上的一切（密码框通常会规避，但聊天、邮件都在内）。优先选全本地存储的方案（Screenpipe、ActivityWatch），并用其数据权限配置限制 AI 可访问的范围。
  • 成本：执行层 agent 每一步都要调用视觉模型，重度使用时 API 费用可观；本地部署 UI-TARS-1.5-7B 需要一张够用的 GPU。OpenAdapt 的「编译后零模型调用」在成本上是异类优势。
  • 部署位置：这些工具都需要图形桌面环境，要装在你自己的电脑上——HPC 集群节点（无 GUI）跑不了执行层，但可以用集群 GPU 托管 UI-TARS 模型供本地 agent 远程调用。
  • 可靠性：GUI agent 在 OSWorld 上最好成绩约 72%，意味着复杂任务仍有失败率。涉及不可逆操作（付款、发送、删除）务必开确认模式。
